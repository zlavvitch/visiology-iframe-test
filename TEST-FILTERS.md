# Проверка пяти фильтров

1. Заменить код технического виджета целиком содержимым `public/visiology-filter-bridge.txt`, сохранить лист.
2. Авторизоваться в Visiology в том же браузере. Открыть ссылку на этот лист из «Дизайнера» в тесте.
3. Дождаться READY со всеми пятью ID и GUID из README. Старый принимающий код не подходит.
4. Применить МО: пустое поле означает Все ([]). Затем ввести точное существующее значение и применить, снова выбрать Все.
5. Отдельно применить врача и должность, проверить значения и данные. Проверить повторное применение и изменение на другие существующие строки.
6. Применить сентябрь 2026. Проверить, что фильтр периода действительно выбирает месяц, а не только 1 сентября. Если подтверждения нет, сохранить READY и ERROR с observed: нельзя считать месячную семантику подтверждённой по одной дате.
7. Применить даты 01.08–30.09.2026, затем одну дату и другой диапазон. Проверить календарь и данные, отдельно проверить сброс дат.
8. Применить все пять; проверить влияния МО → врач → должность → период → даты. Порядок задаётся конфигом виджета. Если фильтры сбрасывают друг друга, итоговая проверка вернёт ERROR.
9. Повторить применение несколько раз без переоткрытия. Проверить возврат к исходным значениям.
10. При тайм-ауте проверить фактический выбор: повтор и откат автоматически не выполняются. После восстановления READY повторить действие вручную.

Входные значения — примеры пользователя, не перечень всех доступных значений. Применение пяти фильтров последовательное и не атомарное. 55 секунд — предел ожидания всего набора на стороне теста. RESULT подтверждает выбор API, а не завершение загрузки данных.

Локально: `npm run build`, `node --test tests/filter-recovery.test.cjs`. Проверки макета не подтверждают поведение месячного виджета реальной Visiology.
