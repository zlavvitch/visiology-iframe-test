# Тест дат и ГКБ

Вставить public/visiology-filter-bridge.txt вместо прежнего кода технического виджета и сохранить лист. Оба фильтра должны быть на этом листе. В тестовой странице открыть ссылку на этот лист из Дизайнера. Требуется действующая сессия Visiology в том же браузере.

- Даты: 49649e68eaaf4b37a20a88a9f33681b3. Исходный диапазон: 2026-03-15T21:00:00.000Z — 2026-10-12T20:59:59.999Z, то есть 16.03–12.10.2026 по Москве. Исходный диапазон фиксирован, не пересчитывается ежедневно.
- ГКБ: e2fed87a050646b4a405891db926f42a. Обычный фильтр: ГКБ 1 и/или ГКБ 15. Другие строки запрещены конфигурацией теста.
- Прежний фильтр да/нет в этом сценарии не устанавливается.

Кнопки позволяют передать даты и ГКБ отдельно или вместе. Ничего не отправляется автоматически при открытии. «Восстановить исходные значения» явно отправляет указанный диапазон и обе ГКБ. Сброс отправляет [], что не равно исходному выбору.

Даты передаются ISO-строками. Виджет извлекает московский календарный день и создаёт локальный Date на этот день. Используется setDateFilterSelectedValues(guid, dates, false): useTime=false отключает учёт времени суток. Параметр документирован начиная с 3.16: https://visiology-doc.atlassian.net/wiki/spaces/3v16/pages/1540718593/Visiology%2BPlatform%2B3.16 . Проверить поведение в используемой 3.19.

«Одна дата» передаёт один календарный день через [Date]. Отдельно проверить диапазон с одинаковой календарной датой начала и конца: он передаёт два одинаковых календарных дня. Эти сценарии не считаются автоматически эквивалентными.

Проверка getSelectedValues сравнивает календарные дни: в присланном журнале API возвращает даты как UTC 00:00, а отправитель — границы московских суток. Оба формата нормализуются в один день. Одиночный день также допускает ответ [день, день]. Другие времена не угадываются. Если API вернёт другую структуру или нормализует границы, тест сообщит ERROR с requested и observed. Это означает отсутствие подтверждения, а не доказанный отказ установки. В таком случае проверить календарь и данные, сохранить журнал для уточнения адаптера. Сброс также может нормализоваться к полному диапазону.

Порядок набора: даты, затем ГКБ. Перед началом проверяется весь набор, после применения повторно проверяется итоговый выбор. Отката нет; возможны промежуточные пересчёты. RESULT подтверждает выбор, но не завершение запросов данных и не корректность расчётов. Влияния фильтров и повторная перезагрузка листа требуют проверки в Visiology.

Проверки: одна ГКБ; обе ГКБ; короткий диапазон; одна дата; диапазон одного дня; оба фильтра; повторный набор; сброс отдельно каждого; восстановление defaults. Следить за календарём и связанными виджетами.

При повторном исполнении скрипта с той же конфигурацией сохраняются обработчик, session и незавершённая команда. Полная смена экземпляра обнаруживается по instanceId: сайт снимает ожидание с предупреждением и восстанавливает связь через HELLO, без повтора SET_FILTERS. После тайм-аута также восстанавливается только связь. Поля можно редактировать во время ожидания; кнопки применения ждут завершения команды.

Сборка и регрессионные тесты пройдены: node --test tests/filter-recovery.test.cjs. Проверены формат дат из журнала, повторный запуск виджета во время команды, второй набор, тайм-аут и восстановление связи без повторной установки. Реальные даты, влияния и данные в Visiology проверяет пользователь после установки виджета.
