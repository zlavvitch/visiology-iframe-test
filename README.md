# Тест управления фильтрами Visiology через iframe

Текущий тест настроен на пять фильтров нового листа. Старые даты и ГКБ заменены; принимающий код на листе также нужно обновить.

| ID | Название | GUID | Режим | Исходный выбор |
| --- | --- | --- | --- | --- |
| med_org | Фильтр МО | 34ed3988cfdd4498a73ef184ba8e9cd8 | single | Все: [] |
| doctors | Фильтр врач | ec500187479f4be3b4ff67ff87cb2950 | single | Абаева М. П. |
| positions | Фильтр должность | 18221ff86f214933af675eae17ee83f2 | single | Врач-терапевт участковый |
| months | Фильтр период главный | 470ae632a05c455ea79715236b4a195b | single | 2026-09-01T00:00:00Z |
| dates | Фильтр по датам | c7e385e7d084417a891099e3c5a79d8d | date | 01.08.2026–30.09.2026 |

МО, врач и должность вводятся точными строками: справочник значений не предоставлен. Пустой МО отправляется как []; пустые врач и должность запрещены. Период — обычный одиночный фильтр. Передаётся точный строковый ключ `2026-09-01T00:00:00Z` через `setFilterSelectedValues(guid, [[value]], callback)`, без преобразования в Date и без добавления миллисекунд. Даты диапазона передаются как границы московских суток.

## Установка и запуск

1. Вставить `visiology/filter-bridge.js` в отдельный технический виджет на том же листе, что все пять фильтров. Сохранить дашборд. Копия для скачивания — `public/visiology-filter-bridge.txt`.
2. Проверить `USER_CONFIG.allowedOrigin`: сейчас это `https://visiology-iframe-test.vercel.app`. Для другого адреса заменить точным origin без пути и завершающего слеша.
3. Авторизоваться в Visiology в соседней вкладке того же браузера.
4. Открыть стенд и вставить ссылку из режима «Дизайнер» именно на лист, включая `sheet`.
5. Дождаться подтверждения связи, применить каждый фильтр отдельно или весь набор. Повторить изменение несколько раз.

Приложение не отправляет исходные значения автоматически при открытии. Возврат к исходным значениям — явная команда. Диапазон фиксированный, не «по вчерашний день».

## Обмен и восстановление

HELLO → READY → SET_FILTERS → RESULT / ERROR. Отправитель проверяет origin, channel, session, источник, instanceId и requestId. Начальный about:blank не получает сообщения. READY сверяет настроенные GUID. HELLO продолжает проверять связь после подключения.

При пересчёте виджет повторно использует текущий обработчик и сохраняет команду. При смене экземпляра или тайм-ауте интерфейс прекращает ожидание и восстанавливает связь; команды автоматически не повторяются. Тайм-аут ответа стенда — число отправленных фильтров × 10 секунд + 5 секунд (55 секунд для всех пяти), подтверждения одного фильтра — 10 секунд.

Даты передаются ISO-строками UTC. Принимающая сторона определяет календарный день Москвы, вызывает setDateFilterSelectedValues с useTime=false и сравнивает календарные дни с getSelectedValues. Это учитывает наблюдавшийся возврат дат в UTC-полночь. Изменение временной зоны требует адаптации кода.

## Ограничения

Применение последовательное, не атомарное: возможны частичные изменения и влияния между фильтрами. Нет автоматического отката; тайм-аут не отменяет API. RESULT подтверждает выбор, а не загрузку всех данных. Сброс [] требует отдельной проверки поведения конкретного фильтра. Исключающие фильтры и иерархические значения не реализованы.

SSO, права доступа и CSP код не настраивает. Требуется действующая сессия браузера и разрешённое встраивание. Панели «Дизайнера» не скрываются.

## Проверка

Предыдущий вариант с датами и ГКБ был подтверждён пользователем. Новый набор из пяти фильтров проверен сборкой и макетом API; проверка на реальном листе ещё предстоит. Автоматические проверки используют макет API, не реальный браузер. Дополнительные сценарии: `TEST-FILTERS.md`.

```bash
npm ci
npm run build
node --test tests/filter-recovery.test.cjs
npm run dev
```

Для локального запуска нужно согласовать allowedOrigin с адресом локального приложения. При изменении принимающего кода синхронизировать `visiology/filter-bridge.js` и `public/visiology-filter-bridge.txt`, затем переустановить код виджета в Visiology.
