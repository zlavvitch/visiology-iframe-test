# Тест управления фильтрами Visiology через iframe

Текущий вариант управляет двумя фильтрами: календарными датами и обычным фильтром ГКБ. Исходный тест «да/нет» на проекте «Роверы» заменён конфигурацией ниже.

| Имя | GUID | Режим | Значения по умолчанию |
| --- | --- | --- | --- |
| dates | 49649e68eaaf4b37a20a88a9f33681b3 | date | 16.03.2026–12.10.2026, Москва |
| hospitals | e2fed87a050646b4a405891db926f42a | multiple | ГКБ 1, ГКБ 15 |

## Установка и запуск

1. Вставить `visiology/filter-bridge.js` в отдельный технический виджет на том же листе, что оба фильтра. Сохранить дашборд. Копия для скачивания — `public/visiology-filter-bridge.txt`.
2. Проверить `USER_CONFIG.allowedOrigin`: сейчас это `https://visiology-iframe-test.vercel.app`. Для другого адреса заменить точным origin без пути и завершающего слеша.
3. Авторизоваться в Visiology в соседней вкладке того же браузера.
4. Открыть стенд и вставить ссылку из режима «Дизайнер» именно на лист, включая `sheet`.
5. Дождаться подтверждения связи, применить даты, ГКБ или оба фильтра. Повторить изменение несколько раз.

Приложение не отправляет исходные значения автоматически при открытии. Возврат к исходным значениям — явная команда. Диапазон фиксированный, не «по вчерашний день».

## Обмен и восстановление

HELLO → READY → SET_FILTERS → RESULT / ERROR. Отправитель проверяет origin, channel, session, источник, instanceId и requestId. Начальный about:blank не получает сообщения. READY сверяет настроенные GUID. HELLO продолжает проверять связь после подключения.

При пересчёте виджет повторно использует текущий обработчик и сохраняет команду. При смене экземпляра или тайм-ауте интерфейс прекращает ожидание и восстанавливает связь; команды автоматически не повторяются. Тайм-аут ответа стенда — 25 секунд, подтверждения одного фильтра — 10 секунд.

Даты передаются ISO-строками UTC. Принимающая сторона определяет календарный день Москвы, вызывает setDateFilterSelectedValues с useTime=false и сравнивает календарные дни с getSelectedValues. Это учитывает наблюдавшийся возврат дат в UTC-полночь. Изменение временной зоны требует адаптации кода.

## Ограничения

Применение последовательное, не атомарное: возможны частичные изменения и влияния между фильтрами. Нет автоматического отката; тайм-аут не отменяет API. RESULT подтверждает выбор, а не загрузку всех данных. Сброс [] требует отдельной проверки поведения конкретного фильтра. Исключающие фильтры и иерархические значения не реализованы.

SSO, права доступа и CSP код не настраивает. Требуется действующая сессия браузера и разрешённое встраивание. Панели «Дизайнера» не скрываются.

## Проверка

Пользователь подтвердил работу после исправления сохранения обработчика и сравнения дат. Автоматические проверки используют макет API, не реальный браузер. Дополнительные сценарии: `TEST-FILTERS.md`.

```bash
npm ci
npm run build
node --test tests/filter-recovery.test.cjs
npm run dev
```

Для локального запуска нужно согласовать allowedOrigin с адресом локального приложения. При изменении принимающего кода синхронизировать `visiology/filter-bridge.js` и `public/visiology-filter-bridge.txt`, затем переустановить код виджета в Visiology.
