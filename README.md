# Visiology внутри React — проверка фильтра

GUID: `09712aeaff3e4d75955d1b9a0652c087`. Допустим только одиночный выбор: `да` либо `нет`. Исходное значение — `да`; открытие стенда само по себе фильтр не меняет.

## 1. Установить принимающий код Visiology

На тестовом листе с этим фильтром создайте отдельный служебный виджет с редактором JavaScript. Вставьте весь файл `visiology/filter-bridge.js` в его редактор кода. Существующий код фильтра заменять не нужно. Сохраните дашборд. Виджет с кодом должен выполняться на открываемом листе.

Код допускает сообщения только от родительского стенда `https://visiology-iframe-test.vercel.app`, с известным протоколом и текущим идентификатором сессии. GUID задан внутри принимающего кода: сообщения не могут выбрать другой фильтр. Значения проверяются; пустой и множественный выбор не предусмотрены.

Если сначала хочется исключить iframe, проверьте вручную в консоли нужного окна Visiology:

```js
visApi().getSelectedValues('09712aeaff3e4d75955d1b9a0652c087')
```

Ожидаемый формат — `[["да"]]` или `[["нет"]]`. Если API недоступен в выбранном контексте консоли, используйте редактор кода виджета.

## 2. Обновить React-проект

Скопируйте из архива в существующий локальный Git-проект файлы `src/main.jsx`, `src/style.css`, `README.md` и папку `visiology`. Остальные файлы проекта и зависимости не менялись. Сохраните существующие `.git` и `.vercel`.

Из папки существующего проекта:

```bash
npm run build
git add src/main.jsx src/style.css README.md visiology/filter-bridge.js
git commit -m "Add single filter messaging test"
git push origin main
```

Дождитесь Ready в Vercel, откройте production-адрес и обновите страницу. Публикация через Git выполняется пользователем; архив сам по себе сайт не обновляет.

## 3. Проверить

1. В обычном браузере войдите в Visiology в отдельной вкладке и убедитесь, что данные доступны.
2. Откройте `https://visiology-iframe-test.vercel.app/` в том же браузере.
3. Вставьте свою HTTPS-ссылку на тестовый лист и нажмите «Открыть дашборд».
4. Дождитесь «Связь установлена». Если ответа нет, проверьте, что код установлен на открытом листе, сохранён и выполняется; проверьте Console. После установки кода переоткройте дашборд или нажмите «Проверить связь».
5. Выберите `нет` и нажмите «Применить фильтр». Проверьте выбор внутри Visiology и пересчёт зависимых виджетов.
6. Повторите для `да`, затем повторно передайте `да`: выбор должен сохраниться.
7. Переоткройте дашборд и вручную передайте выбранное в React значение ещё раз.

Ответ RESULT отправляется только при совпадении `getSelectedValues` с запрошенным одиночным выбором. Это подтверждает значение фильтра, но не завершение запросов всех виджетов. Повтор уже выбранного значения подтверждается без повторного вызова установки. Возврат к исходному состоянию выполняется передачей `да`, а не очисткой фильтра.

## Границы теста

Стенд не реализует SSO, не выдаёт прав на данные и не меняет CSP. Используется текущая сессия браузера. Подтверждённое встраивание в одном браузере не гарантирует работу авторизации у всех пользователей.

Принимающий код поддерживает прямое окно дашборда и цепочку вложенных окон одного origin. Если Visiology размещает исполняемый виджет в другом origin или ограниченном sandbox, потребуется отдельно изучить структуру окон. Непроверенные origin не разрешаются.

Production-сборка и проверки логики с макетом API выполнены локально. Применение к реальному дашборду должно быть проверено пользователем после установки кода.

## Локальный запуск

```bash
npm ci
npm run dev
```

Получать сообщения с localhost принимающий код по умолчанию не разрешает. Для локального теста укажите точный origin локального стенда в `USER_CONFIG.allowedOrigin`; перед публикацией верните production-адрес.
