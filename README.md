# Тест iframe Visiology — этап 1

Минимальный React + Vite стенд. Проверяет встраивание дашборда и позволяет вручную отметить результат. Передача фильтров и авторизация проекта М пока не реализованы.

## Локальный запуск

Требуется Node.js 22.12+ (или новее).

```bash
npm ci
npm run dev
```

Откройте адрес из терминала и вставьте HTTPS-ссылку на тестовый дашборд.

## Размещение на Vercel

Из папки проекта выполните:

```bash
npx vercel
```

Войдите в свой аккаунт Vercel по предложенной CLI процедуре, выберите нужный аккаунт/команду и создайте проект. Текущая папка — корень проекта. Настройки сборки уже заданы в vercel.json. Для production-развёртывания используйте `npx vercel --prod`.

Альтернатива: загрузите исходники в свой Git-репозиторий и импортируйте его в Vercel. Framework: Vite; Build Command: `npm run build`; Output Directory: `dist`.

Стабильный адрес развёртывания потребуется администратору Visiology для разрешения встраивания. Предварительные ссылки разных развёртываний могут иметь разные origin.

## Проверка

1. Откройте стенд в инкогнито из той сети/VPN, где будут работать пользователи.
2. Вставьте ссылку на тестовый дашборд и нажмите «Открыть дашборд».
3. Убедитесь, что дашборд отображается без страницы входа и работает.
4. При проблеме откройте F12 → Console / Network. Сохраните текст ошибки и HTTP-статус проблемного запроса. Перед отправкой скриншотов удалите токены и другие секреты.
5. Нажмите кнопку подтверждения результата. Это ручная отметка, а не автоматическая проверка.

Событие iframe load не доказывает успешную загрузку: оно может возникнуть даже при блокировке. Стенд не читает DOM Visiology другого origin и не может автоматически определить страницу входа или готовность данных.

Ссылка не вшита в исходники, не сохраняется в localStorage и не отправляется backend стенда. Браузер обращается по ней непосредственно к Visiology. Стенд не содержит аналитики. Разрешения iframe пока не ограничены sandbox, чтобы не блокировать штатные скрипты Visiology; допустимый набор ограничений уточняется отдельно.

## Следующий этап

Для проверки фильтров потребуются GUID одного фильтра, точный пример значения и принимающий JavaScript-код на тестовом дашборде. Здесь предусмотрен только журнал сообщений от окна iframe с совпадающим origin. Если Visiology сама сообщения не отправляет, журнал будет содержать только локальные события. Названия сообщений ещё не определены.
